# 本の検索 — 流れと、よく読まれている本が出なかった原因（2026-10-02）

「本を追加で探しても目当ての本が出てこない」を直すときに、まずここを読む。表紙の取得は `docs/cover-pipeline.md`。

## 0. オーナーの報告（2026-10-02・iPhone・スクリーンショット）

「本棚に入っていない読みたい本の検索レベルが低い。考え方という稲盛さんの本を追加しようとしたが、考え方と入力しても出てこない」。

検索語「考え方」の結果は **17 件**。上から「アートディレクターの流儀：考え方・つくり方の…」「アートとしてのソフトウェア：機能と表現の考え方」(1986)「アートは女を変える」(1994)「ROI経営実践法」(1981)「Rで学ぶマルチレベルモデル」(2018)…。**表紙はすべて色の板**、著者は「Heckel, Paul, 酒井, 邦秀, 1945-」のような NDL の書き方。目当ての 稲盛和夫『考え方 人生・仕事の結果が変わる』（大和書房・2017・**ISBN 978-4-479-79573-5**＝4479795731。依頼文の 9784479796015 は別の番号）は無い。

## 1. 直す前の流れ（2026-10-01 まで）

```
本を追加の検索欄（AddBookModal / BookSearchModal の searchBooksByQuery）
  ├ ISBN → openBD → Google（その本だけ）
  └ 書名・著者 → 端末から searchBooksAdvanced を順に:
       1. NDL OpenSearch  title=<語>  cnt=50     ← ほぼ毎回ここで終わる
       2. 0 件なら NDL creator=<語>
       3. 0 件で語が 2 つ以上なら title/creator の組み合わせ
       （各段: NDL の結果の ISBN を openBD にまとめて問い合わせ、summary.cover があれば表紙に）
       （NDL が 0 件か失敗したときだけ Google Books q=<語>（鍵なし・端末から））
  → 結果は NDL が返した順のまま（並べ替えなし）。7 日間 localStorage に覚える
```

初日クイックスタート・AI 選書の追加・本の手動追加の照合（`searchBooks` / `searchBooksFlat`）も同じ NDL 優先の流れ。

## 2. 原因

| # | 症状 | 原因 |
|---|---|---|
| 1 | **辞書順に並ぶ** | NDL OpenSearch は関連度や人気で並べない。返ってくる順は **書名の読みの順**（ア… → 「ROI」＝アールオーアイ → 「Rで」＝アール… → カ…）。端末はその順のまま出していた（`mergeResults` は先に来た順を保つだけ・並べ替えなし）。スクリーンショットの「ア」「R」で始まる本が先頭なのはこのため |
| 2 | **目当ての本が無い** | 1 と同じ理由で、`cnt=50` で **読みの順の先頭 50 件だけ**を受け取る。「考え方」を書名に含む本は NDL に数千件あり、「カンガエカタ」は 50 件より後ろ。さらに記事（雑誌の中の 1 本）を除くので 50 → 17 件。**人気の本（売れている・読まれている）を先に出す仕組みがどこにも無かった** |
| 3 | **表紙が無い** | 検索の結果の表紙は openBD の `summary.cover` だけ（NDL の書影は「無い本にも No image を返す」ので入れない方針・cover-pipeline §2-3）。openBD は出版社が登録した新しめの本しか持たず（表紙は約 4 割）、読みの順の先頭に来る古い本・学術書・ISBN の無い本はほぼ全滅。楽天（表紙のカバー率が最も高い）は表紙探し（`/api/cover`）でしか使っておらず、検索には使っていなかった |
| 4 | **著者が「Heckel, Paul, 酒井, 邦秀, 1945-」** | NDL の `dc:creator` は「姓, 名, 生没年」。端末は複数の creator を「, 」でつないでいたので、人の切れ目も分からない |
| 5 | 古い結果が残る | 1〜4 の結果を 7 日間 localStorage に覚えていた（同じ語なら直しても 7 日間同じ） |

## 3. 直した流れ（2026-10-02〜）

```
本を追加の検索欄（searchBooksByQuery）・初日クイックスタート等（searchBooks）
  ├ ISBN → 今までどおり openBD → Google（その本だけ・サーバーの検索は通らない）
  └ 書名・著者 → サーバー /api/cover?search=<語>（api/_bookSearch.js）
       ① 楽天ブックス（RAKUTEN_APPLICATION_ID + RAKUTEN_ACCESS_KEY + RAKUTEN_APP_URL）・売上順（sort=sales）・30 件
            語が 1 つ:  BooksBook/Search title=<語>  →  BooksTotal/Search keyword=<語>&booksGenreId=001（著者名でも当たる）
            語が 2 つ以上: BooksTotal/Search keyword=<語>（AND）→ 関係する本が 5 冊未満なら いちばん長い語で BooksBook title=
            楽天は続けて呼ぶと 429 になりやすいので 1 回ずつ順番に。429 などは次の手へ進む
       ② Google Books（GOOGLE_BOOKS_API_KEY があるときだけ・①と同時に）
       ③ NDL OpenSearch（①②で関係する本が 5 冊未満のときだけ・title= か any=・30 件）＋ openBD の表紙（1 回でまとめて）
       ④ 重なりを除く（dedupeBooks）→ 並べ替える（rankBooks）→ 最大 30 冊
       → { results: [{ title, subtitle, author, publisher, pubdate, pubYear, isbn, cover, sales, review, source }] }
       覚える: サーバーのインスタンスの中 30 分・CDN は結果ありで 1 時間（0 件は 5 分）。失敗は覚えない（502・no-store）
     サーバーが失敗・0 件 → 端末の検索（直す前の 1 の流れ）に切り替え、結果を同じ並べ方で並べ直す（rankLocalResults）
```

- 新しい Vercel 関数は増やしていない（`api/cover.js` の `?search=`。関数の数は 10 のまま・Hobby の上限 12）
- 呼び出しの回数制限は `/api/cover` と同じ（IP ごとに 1 分 30 回）
- 楽天の呼び出し（鍵・Referer・Node の https）は `api/_rakuten.js` で表紙探しと共有
- 端末はサーバーの結果を覚えない（失敗や 0 件を 7 日残さない）。端末だけの検索の覚えは `bookSearchCache:v2`（旧 v1 は捨てる）・0 件は 1 日・失敗は覚えない
- 表紙: 楽天の `largeImageUrl`（`_ex=420x420` に拡大・noimage は表紙なし）→ Google の thumbnail（https に）→ openBD。CSP の `img-src` は `thumbnail.image.rakuten.co.jp` を許可済み（変更なし）。選んだ本の表紙は、見えていたものをそのまま保存（`App.jsx pickBookFromAdd`）

## 4. 並べ方（api/_bookRank.js の `scoreBook`）

検索語を空白で語に分け、著者名に入っている語（「稲盛」「稲盛和夫」）と、書名を探す語（「考え方」）に分ける。比べるときは全角半角・大小・ひらがな/カタカナをそろえ、空白と記号を落とす。「核の書名」＝副題を落とした書名（最初の空白・「：」まで。末尾の（単行本）なども外す）。

**2 段で並べる**（2026-10-02 ui-critic「段が入れ替わらないように」）: まず **一致の段**（下の表の上 6 行＝`match`）、同じ段の中で **よく読まれているか**（残りの行＝`quality`）。`scoreBook = match × 1000 + quality`（quality は −36〜+67 なので段はまたがない）。人気の本でも「途中にある」は「まるごと同じ」より上に来ないし、書名に語がある古い本は副題だけの新しい本より上（テスト: 「会計の基本的な考え方」＞「Rで学ぶマルチレベルモデル：統計の考え方」）。

| 項目 | 点 |
|---|---|
| **一致の段（match）** | |
| 核の書名（または書名全体）が書名の語とまったく同じ（「考え方」） | +100 |
| 核の書名が書名の語で始まる（「考え方の教室」） | +55 |
| 核の書名の途中にある（「仕事の考え方」） | +40 |
| 副題・書名の後ろのほうにだけある（「アートディレクターの流儀：考え方・…」） | +12 |
| 著者名に入っている語（1 語ごと・2 語まで） | +45 |
| 書名にも著者にも無い語（説明文で当たっただけ）1 語ごと | −40 |
| **同じ段の中の並び（quality）** | |
| 楽天の売上順の位置（1 位 +30 → 30 位 0） | 0〜+30 |
| レビュー件数（6 × log10(1 + 件数)） | 0〜+15 |
| 表紙がある / ISBN がある | +10 / +6 |
| 新しさ（1990 年から 5 年ごとに +1） | 0〜+6 |
| 図書館（NDL）にしか無く、ISBN が無いか 1990 年より前 | −20 |
| 図書館（NDL）にしか無い（それ以外） | −8 |
| 大学出版会・学会・研究所の出版 | −8 |

- 同じ点なら元の順（楽天の売上順）
- 語が書名・副題・読み・著者のどこにも無い本は、関係する本が 3 冊以上あるときは外す（楽天の keyword は説明文にも当たるため）
- 例（テスト `api/_bookRank.test.js`）: 「考え方」で 稲盛和夫『考え方』（match 100）が、「アートディレクターの流儀：考え方…」（match 12）より上。同じ「考え方」という書名の本どうしは売上・レビュー・表紙で 稲盛和夫『考え方』が上。「考え方 稲盛」「稲盛和夫 考え方」でも 1 位
- NDL・端末の検索の「書名 : 副題」「書名：副題」「書名 — 副題」は、副題が無いときだけ書名と副題に分ける（`splitSubtitle`・行で副題を弱く出す・保存する書名は核の書名）

### 重なりを除く（`dedupeBooks`）

- ISBN が同じ（ISBN-10 も 13 桁にそろえる）なら 1 冊
- 書名＋副題＋先頭の著者（または核の書名＋先頭の著者）が同じで、片方に ISBN が無いか取得元が違うなら 1 冊。**同じ取得元で ISBN が違う本（単行本と文庫）は両方残す**
- 残すのは: 楽天の書名・表紙（無ければほかの表紙）・きれいな著者名（生没年や「, 」の無い方）・いちばん良い売上順・多い方のレビュー件数

### 著者名（`formatAuthors` / `formatPersonName`）

- 「稲盛, 和夫, 1932-2022」→「稲盛和夫」・「Heckel, Paul」→「Paul Heckel」・「コヴィー, スティーブン・R.」→「スティーブン・R.・コヴィー」・「ドラッカー, P.F.」→「P.F.ドラッカー」
- 生没年・「著」「[著]」を落とす（「訳」「編」は残す）・漢字の間の空白を詰める（「稲盛 和夫」→「稲盛和夫」）
- 連名は「、」でつなぐ（楽天の「楠木建/杉浦泰」・openBD の「稲盛和夫／著」も）。同じ人は 1 回
- 「, 」でつないだだけの古い文字列（「Heckel, Paul, 酒井, 邦秀, 1945-」）も、生没年と 2 つ組で人を分けて「Paul Heckel、酒井邦秀」
- 端末の NDL・openBD・Google の結果も同じ関数で整える（取り込み（ブクログ・読書メーター・Kindle）の著者は元から「稲盛和夫」の形なので触らない）

## 5. 本番で確かめる

`https://orime.vercel.app/api/cover?health=1` の `search`:

| 項目 | 意味 | 期待 |
|---|---|---|
| `search.status` | 楽天の検索の HTTP の番号 | 200 |
| `search.found` | 「考え方」で 1 冊以上見つかった | true |
| `search.top3` | 稲盛和夫『考え方』（9784479795735）が上位 3 冊に入った | true |
| `search.sources` | 楽天・Google・NDL それぞれ `ok` / `error` / `off`（鍵なし）/ `skip`（呼んでいない） | rakuten: ok |

1 語だけ試すときは `https://orime.vercel.app/api/cover?search=考え方`。

## 6. 注意

- **楽天 API の上限**: アプリ ID ごとにおよそ 1 秒 1 回。1 回の検索で楽天を最大 2 回（順番に）呼ぶ。表紙探しと同じ ID を使うので、利用者が増えたら 429 が出やすくなる → サーバーの 30 分の覚え・CDN の 1 時間で同じ語の再検索は楽天を呼ばない。429 のときは Google・NDL で返す（並べ方は同じ・表紙は減る）
- **iOS アプリ**: 端末側（サーバーの検索を先に呼ぶ・副題・件数の案内・端末の検索の並べ直し・著者名）は **アプリの出し直しで届く**。サーバーの検索（`/api/cover?search=`）は Vercel の公開ですぐ効くが、出し直す前のアプリはそれを呼ばない（今までどおり端末から NDL）
- 楽天の `BooksTotal` の keyword は説明文にも当たる → 書名・著者に語が無い本は外す（関係する本が 3 冊以上あるとき）
- お試しモード: `/api/cover?search=` は見本のカタログ（`src/demo/demoBookSearch.js`・表紙は端末で作った絵）。`&search=old` で直す前の流れ（端末から NDL・辞書順の再現）、`&search=fail` で失敗。ui-shots の `add-book-kangaekata` / `add-book-kangaekata-author` / `add-book-kangaekata-old`
