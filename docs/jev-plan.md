# Jev（TypeSafe AI）を Orime に入れる計画（2026-10-02）

> オーナー要望（2026-10-02）「Jev を進めたい。今のシステムで使えそうなところを洗い出して、入れ込むことでよくなるところには組み込みたい」

## 0. 結論（先に）

- **入れた（既定は止めたまま・スイッチで入る）**: ① 相談の「今回の質問にとくに関係がありそうなメモ」を Jev で選ぶ（`memo_relevance`）② メモを保存したあとの **タグの提案**（`memo_filing`）。②は画面ごと新しく作り、Jev が無くても端末の中の決め方（AI なし）で動く。
- **先に評価してから**: 問いの種類（`intent`＝本を探す／相談／行動を決めたい）。サーバーの問い・評価の見本は用意したが、アプリにはまだつないでいない。
- **入れない**: メモが答える相談・すべての本の検索・つながるメモ（「AI を使わない・トークンを使わない」と約束している）、払い戻しの判定（お金にかかわる判断は監査できる決まりで）、ほか（§2）。
- **入れるかどうかは用途ごとに、日本語の見本で今の決め方をはっきり上回ったときだけ**（§4 の基準）。鍵が届いたら `node scripts/jev-eval.mjs` を 1 回流して決める（§6）。

## 1. Jev とは（確かめたこと）

TypeSafe AI が 2026-09-15 に発表した「System One」の判断のモデル。**文を書かない**。状況（`state`）と、決めた形の問い（`questions`）を送ると、問いごとに型の決まった答えと確率だけを返す（形の外の値は返さない）。問いは同時に決める。

| 項目 | 内容 | 出典 |
|---|---|---|
| 問いの形 | `noul`（はい/いいえ・答えは「はい」の確率 0〜1・確信の欄は無い）／`choice`（名前つきの選択肢から 1 つ＋選択肢ごとの確率＋確信・選択肢は 255 個まで）／`score`（低い順の段階＋点数＋確率＋確信） | 公式 docs の検索の抜き書き・複数の解説 |
| 送り先 | `POST https://api.typesafe.ai/v1/systemone`（`Authorization: Bearer <鍵>`）。OpenRouter 経由は `POST https://openrouter.ai/api/v1/systemone`（モデル `typesafe/jev-1.13`） | 同上 |
| 送る形 | `{ model: 'jev-latest' \| 'jev-1.13.0', state: 文字列/オブジェクト/配列, questions: { <snake_case の名前>: { type, instructions, criteria } } }` | 同上 |
| 返る形 | `{ model, answers: { <名前>: { type, noul } \| { type, choice, confidence, probabilities } \| { type, score, confidence, legend, probabilities } }, usage: { input_tokens, output_tokens } }` | 同上 |
| 上限 | 1 回 64k トークン・「state＋いちばん長い問い」で 32k（超えると 400 `max_tokens_exceeded`）。毎分 1,200 回・毎秒 25 万トークン（早期アクセスの値）。1 回の問いの数は「1〜6」とする解説と「決まりは無い」とする解説がある | 解説・GitHub の issue |
| 速さ・値段 | 約 70〜500ms。入力 $0.042 / 100 万トークン・出力は無料（`think` を使ったときだけ出力が付く） | 発表・OpenRouter |
| 日本語 | 「扱えるが英語ほどの精度ではない」（公式）。日本語の検証では 5 択の振り分けで 96% 一致の報告と、大きな問いを小さな はい/いいえ に分けると当たりやすいという報告 | 依頼文・日本語の解説記事 |
| データ | 顧客のデータを学習に使わない。サーバーは米国。保存ゼロ（zero retention）は Enterprise だけ | 依頼文（**入れる前に最新の規約で確かめる**） |

⚠️ **公式の docs.typesafe.ai・openrouter.ai はこの作業環境から開けなかった**（外へのつなぎ先の制限）。形は検索の抜き書きと第三者の解説で確かめた。違ったときに直すのは `api/_jev.js` だけ（`readAnswer` が `answers` の無い形・`noul` が `probability` / `value` の名前などの揺れも読む）。§8。

## 3. 入れたもの（今すぐ）

### 3-1. 流れ

```
アプリ                                      サーバー（/api/claude の中の短い道）                    TypeSafe AI
lib/jev.js askJev(purpose, 材料)  ──→  api/_jevRelay.js
  ・VITE_AI_JEV=on のビルドだけ            ・resolveJevRoute（api/_aiRouting.js の JEV_ROUTES）:
  ・ログインしている                          JEV_ENABLED・JEV_API_KEY・JEV_TASK_<用途>=on・
  ・版 2 の同意がある（聞かない）              プラン（タグの提案はプランの人だけ）・同意の版 2
  ・2.5 秒で打ち切り                         ・材料を切って整え、問いはサーバーが作る（api/_jevTasks.js）
                                            ・毎分 20 回・毎月 600 回（ai_usage の 'jev-YYYY-MM'）
                                            ・api/_jev.js jevDecide: 6 問ずつに分けて同時に ──→  POST /v1/systemone
                                              1.5 秒で打ち切り・どれか失敗したら null         ←──  answers + usage
                         ←──  いつも 200: { jev: { result, ms } } か { jev: null, reason }
null なら今の決め方で続ける
```

- **アプリから届くのは材料だけ**。問いの文はサーバーが作る（改造したアプリが Jev を何にでも使える判断の窓口にしない）。
- **402 / 429 を返さない**（有料プランの画面・トークンの案内を出さない＝裏で使う小さな判断だから）。
- **利用者のトークンからは引かない**。回数と原価は `ai_usage` の `jev-YYYY-MM` 行（`reserve_ai_usage` と `adjust_ai_cost` を流用・**新しい SQL は要らない**）。運営ダッシュボードの AI 利用にも `jev-…` の月として出る。数えられないとき（RPC が無い）は送らない。
- ログは用途・成否・回数・トークン・文字数・時間だけ（メモ・質問の中身と利用者は書かない）。

### 3-2. 相談の関係するメモ（`memo_relevance`）

- 相談の材料は 2 つの塊: **芯**（質問に左右されないメモ一覧・その日のうちは同じ文字＝キャッシュが効く）と **関係するメモ**（質問ごとに変わる塊）。**Jev は後者だけ**を決める（`selectConsultMemos(…, { related })`・芯は Jev があってもなくても 1 文字も変わらない＝テストで確認）。
- 候補: 語片の重なるメモ 20 件 → 重要度の高いメモで 30 件まで（`lib/consultRelevance.js`）。送るのは質問（深掘りでは直前の問いと結論も＝`retrievalQuery`）・候補の一節（160 字まで）・書名だけ。メモの DB の id は送らない（m0〜 の番号）。
- 確率 0.5 以上を高い順に 12 件まで・字数の上限は今と同じ。Jev が「どれも役に立たない」と答えたら関係するメモの塊は空（芯は渡る）。
- 待ち: 歩み（行動・過去の相談）の読み込みと並べて待つ（`ai.js` `buildBrainContext`）。
- 無料プランの相談でも使う（相談の一部・トークンは数えない）。メモが答える相談には使わない（§2 #2）。本ごとに（`pickPerspectiveBooks`）にはまだ使わない（評価のあとで）。

### 3-3. タグの提案（`memo_filing`）

- 画面（SPEC §2・DESIGN §5）: メモを保存したあと、本の詳細のメモ一覧の上に「このメモに合いそうなタグ」と自分のタグのチップ 1〜3 個。押すと付く・もう一度で外す・**勝手には付けない**・× で閉じる。
- 端末の中の決め方（全員・AI なし・`lib/tagSuggest.js`）: 3 文字以上のタグが文に出ている／似たメモ（切れ端を 2 つ以上共有するもの）の近い 10 件に付いているタグの割合（似ている度合いの合計が小さければ割り引く）＋本のタグ。**見逃す側**（§5: 適合率 80%・再現率 18%）。
- Jev（プランの人・版 2 の同意・スイッチ）: 端末の点の高い順＋よく使う順で 16 個まで、タグ 1 つずつ はい/いいえ。確率 0.6 以上を 3 個まで。送るのはメモの文（600 字まで）・書名・候補のタグの名前だけ。
- 計測: `tag_suggest_shown`（n・source=local/jev）・`tag_suggest_added`（source）＝本番で、どちらの決め方のチップがどれだけ押されたかを見る（押された割合＝実際の適合率の目安）。

### 3-4. 同意（App Review 5.1.2(i)）とプライバシー

- アプリの `VITE_AI_JEV=on` のビルドだけ、同意のシートの送り先に TypeSafe AI が加わり（相談＝Anthropic・TypeSafe AI、「タグの提案」の行）、**同意の版が 2** になる（`lib/aiProcessors.js` `buildAiProcessors`）。止めているビルドは版 1 のまま＝使っていない会社のために聞き直さない。
- Jev は**同意のシートを出さない**。版 2 の同意がある人の分だけ送る（アプリ `lib/jev.js`＋サーバー `X-Orime-Ai-Consent` ≥ 2）。
- プライバシーポリシー（`/legal/privacy` 第5〜7条）の TypeSafe AI の行も同じビルドでだけ出る（`AI_JEV_ON`）。`legal/privacy.md`・`company/app-store-submission.md` §6-2 にも書いた。
- AI を使わない機能（メモが答える相談・検索・つながるメモ・共有）は AI なしのまま。タグの提案も、Jev を入れていなければ AI なし。

### 3-5. 原価（1 回・1 か月）

| 用途 | 1 回の入力 | 1 回の原価 | 1 人・1 か月の見込み |
|---|---|---|---|
| 関係するメモ（30 件） | 約 14,000 字＝約 8,500 トークン（日本語 1.1・英語 0.25 で数えて） | **約 ¥0.06**（上振れの見積もり ¥0.13） | 相談 60 回で約 ¥4（上限の 600 回でも ¥76 まで） |
| タグの提案（16 個） | 約 3,600 字 | ¥0.03 未満 | メモ 90 件で ¥3 未満 |
| 問いの種類 | 約 700 字 | ¥0.01 未満 | — |

相談 1 回（Haiku 4.5）は約 ¥3 なので、関係するメモの判断は相談の原価の 2% 前後。手取り ¥900 の式（`docs/ai-routing.md` §3）には影響しない大きさだが、利用者のトークンとは別に数えている（入れたあと `jev-…` 行の `cost_mjpy` で確かめる）。

## 4. 採用の基準（用途ごとに `JEV_TASK_<用途>=on` にしてよい条件）

`node scripts/jev-eval.mjs`（§6）の結果で、**次のすべて**を満たした用途だけを入れる。満たさなければ止めたまま（いまの決め方で十分）。

| 用途 | 質 | 守り | 待ち・失敗 |
|---|---|---|---|
| `memo_relevance` | F1 が今より **+0.15 以上**（今 0.474 → 0.62 以上）かつ 再現率 60% 以上 | 適合率 75% 以上（関係の無いメモを「とくに関係がある」と言わない）・どれも当たらない質問（確定申告）で 1 件も選ばない | p95 1,200ms 以下・失敗（null）5% 以下 |
| `memo_filing` | 再現率が今より **+0.25 以上**（今 18% → 43% 以上） | 適合率 75% 以上・合うタグの無いメモにすすめた 10% 以下 | p95 1,200ms 以下・失敗 5% 以下 |
| `intent` | macro-F1 が今より **+0.20 以上**（今 0.515 → 0.72 以上） | lookup の適合率 90% 以上（相談を「本を探す」に取り違えると答えの形が崩れる）・decide_action の適合率 90% 以上 | p95 800ms 以下（送る前に待つため）。満たしたらアプリへのつなぎ込みを別の作業で |

- 基準を満たしても、入れたら 2 週間は計測（`[jev]` のログの失敗の数・`tag_suggest_added ÷ tag_suggest_shown`・相談の「根拠を見る」の参照の数）を見て、落ちていれば `JEV_TASK_<用途>` を外す（アプリの出し直しは不要）。
- しきい値（0.5 / 0.6）は `--relevance-min` / `--filing-min` で動かして、基準に届くいちばん保守的な値を選ぶ。変えたら `lib/consultRelevance.js` の `JEV_RELEVANCE_MIN`・`lib/tagSuggest.js` の `JEV_MIN` も同じ値に（こちらはアプリの出し直しが要る）。
- 見本は 164 件と小さく、作った本人がラベルを付けた（タグの提案の端末の決め方は、この見本で 2 つの決まりを足して適合率を上げた＝今の決め方の数字はやや甘い）。迷う結果のときは、実際のメモで 20〜30 件足してから決める。

| filing（`suggestTagsLocal`） | 40 件 × 9 タグ＝360 組 | 正解率 89.4%・**適合率 80.0%・再現率 18.2%・F1 0.296**（TP 8 / FP 2 / FN 36）・完全一致 25%・合うタグの無いメモにすすめた 0% |

読み方: 今の決め方は**当たったときは正しいが、見逃しが多い**（再現率 18〜47%）。Jev に期待するのは、適合率を保ったまま見逃しを減らすこと。

## 6. オーナーの手順（アクセスが届いたら）

1. **アクセス**: typesafe.ai の waitlist に登録 → 届いたら console.typesafe.ai/keys で鍵を作る（プレイグラウンドで日本語の問いを 2〜3 試すと感触が分かる）。待たずに試すなら OpenRouter（`typesafe/jev-1.13`・前払いのクレジット）でもよい。
2. **評価**（手元の Mac・ネットにつながる所で・鍵は画面に出さない）:
   ```sh
   JEV_API_KEY=<鍵> node scripts/jev-eval.mjs --repeat 3 --json jev-eval-result.json
   # OpenRouter のとき
   JEV_API_KEY=<OpenRouter の鍵> JEV_ENDPOINT=https://openrouter.ai/api/v1/systemone JEV_MODEL=typesafe/jev-1.13 node scripts/jev-eval.mjs
   ```
   全部で 1 円未満。§4 の表と見くらべる。結果の JSON はチャットに貼ってくれれば読む。
   鍵なしの `node scripts/jev-eval.mjs` は今の決め方だけ（§5 の数字）、`--mock` は偽物の Jev で配線だけを確かめる（数字に意味は無い）。
3. **サーバーのスイッチ**（Vercel の env・すぐ効く・アプリの出し直し不要）: `JEV_API_KEY`・`JEV_ENABLED=true`・基準を満たした用途だけ `JEV_TASK_MEMO_RELEVANCE=on` / `JEV_TASK_MEMO_FILING=on`。
4. **アプリのスイッチ**（ビルド時・iOS アプリは出し直し）: `VITE_AI_JEV=on`。入れたビルドから、同意のシート（版 2）・プライバシーポリシーに TypeSafe AI が出る。**その前に TypeSafe AI の規約で「学習に使わない」を確かめる**（`company/app-store-submission.md` §6-2）。
5. 止めるとき: `JEV_TASK_<用途>` を外す（すぐ・アプリは今の決め方に戻る）か `JEV_ENABLED` を外す（全部）。同意の版はアプリのビルドで決まるので、TypeSafe AI を送り先から外すときだけ `VITE_AI_JEV` を外して出し直す。

## 7. env

| 変数 | 場所 | 既定 | 意味 |
|---|---|---|---|
| `JEV_API_KEY` | サーバー（Vercel） | なし | TypeSafe AI（または OpenRouter）の鍵。**クライアントに出さない** |
| `JEV_ENABLED` | サーバー | なし（止める） | `true` で Jev の中継を使う（全体のスイッチ） |
| `JEV_TASK_MEMO_RELEVANCE` / `JEV_TASK_MEMO_FILING` / `JEV_TASK_INTENT` | サーバー | なし（止める） | 用途ごとのスイッチ（`on`）。`INTENT` はアプリがまだ送らない |
| `JEV_ENDPOINT` | サーバー | `https://api.typesafe.ai/v1/systemone` | https だけ。OpenRouter なら `https://openrouter.ai/api/v1/systemone` |
| `JEV_MODEL` | サーバー | `jev-1.13.0` | OpenRouter なら `typesafe/jev-1.13`（原価はどちらも `jev-1.13` の単価） |
| `JEV_TIMEOUT_MS` | サーバー | 1500（5000 まで） | 打ち切り。アプリ側は 2,500ms |
| `JEV_MAX_QUESTIONS` | サーバー | 6 | 1 回に送る問いの数（多ければ分けて同時に送る）。上限が無いと分かったら 30 にすると往復が減る |
| `JEV_MONTHLY_CALL_LIMIT` | サーバー | 600 | 1 人・1 か月の中継の回数（`jev-YYYY-MM`） |
| `JEV_RATE_PER_MIN` | サーバー | 20 | 1 人・1 分の中継の回数（インスタンスごと） |
| `VITE_AI_JEV` | アプリ（ビルド時） | なし | `on` で送り先に TypeSafe AI・同意の版 2・プライバシーポリシーの行。お試しモードは `?jev=1`（`&jev=down` で使えないとき） |

## 8. 確かめられていないこと（直す場所）

- **API の形**（§1）。違ったら `api/_jev.js` の `sendOne`（送る形・見出し）と `readAnswer` / `answersOf`（返る形）だけを直す。テストは `api/_jev.test.js`。
- **1 回の問いの数の上限**。既定 6 で分けて送る（`JEV_MAX_QUESTIONS`）。
- `noul` の答えの名前（`noul` と書かれている資料に合わせた。`probability` / `value` / `p` / `probabilities.true` も読む）。
- OpenRouter 経由の形が TypeSafe と同じか（「TypeSafe 互換」とある）。
- 日本語での精度（§4 の評価で決める）。
- 規約: 学習に使わない・保存の期間（入れる前に）。
