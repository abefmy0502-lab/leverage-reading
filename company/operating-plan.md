# ⏱ Orime 時間制約オペレーティング・プラン（週8.5時間でKGIに届く設計）

> CEO策定 2026-06-21。**最大の制約＝オーナーの稼働時間（平日30分／休日3時間＝週約8.5時間・月約37時間）**。会社の真実は `company/board.md`。

## 0. 結論
**週8.5時間でもKGI（2026=継続150人）は到達可能。ただし絶対条件は次の3つ。**
1. **オーナーは"手を動かさない"**。あなたの時間は「①AIチームには出来ないこと ②意思決定」だけに使う。制作・コード・文章・分析・調査は**全部CEO（私）＝AIチームが引き受ける**。
2. **自動化とバッチ**。X/Noteは週末にまとめて作り予約投稿。CSはテンプレ。手作業を最小化。
3. **絞る**。KGIに効かないことは一切やらない。

## 1. 役割分担（これが心臓部）
| オーナー（週8.5h）＝顔・手・意思決定 | AIチーム（CEO＝私）＝エンジン（時間制約なし） |
|---|---|
| 実名義アカウント取得・支払・税/口座（Apple/Play/RevenueCat等） | それらの**手順書・トラブル対応**を全部用意 |
| Macでのビルド実行・ストア申請（クリック作業） | コード・設定・申請文・runbookを完成形で渡す |
| **X/Noteの"自分の声"での投稿・返信**（人間味の核） | 投稿文・記事・スレッドを**ドラフト完成形で量産** |
| 重要な意思決定・最終承認 | 選択肢と数字・推奨を提示 |
| ユーザーへの誠実な対応（少数） | 返信テンプレ・FAQを用意 |

> 原則：**「考える・作る・調べる」はAI、「決める・出す・名義」はオーナー。**

## 2. ⭐ 戦略提案：Web先行ソフトローンチ（時間最大の敵＝ネイティブ審査を後ろに回す）
**時間制約下での最重要の組み替え。** ネイティブ化＋App Store審査は、**非専門家のオーナーの限られた時間を最も食う工程**（Xcodeビルド・審査リジェクト対応で数週間の週末が消えうる）。これを"初収益までの道"から外す：

- **第1段：Web版（Stripe）でソフトローンチ**。Web PWAは**既に完成**、Stripe基盤も**実装済**。残りは結線＋ペイウォール＋デプロイのみ＝**オーナーの時間ほぼ不要**（私が実装、オーナーはpush/deploy承認だけ）。Apple審査ゲートなしで**最速で初課金と学習**を得る。
- **第2段：ネイティブ（App決済）を週末枠で並行ビルド** → 整い次第ストア公開（オーナーの本命チャネル）。ソフトローンチで貯めた読者をそのまま送客。
- ※App決済の方針は維持。これは"順番"の最適化（Web=学習と初収益の橋、App=本番チャネル）。手数料はWeb 3.6%＝むしろ高マージン。
- **要・元帥判断**：Web先行ソフトローンチを採るか（CEO強く推奨）。

## 3. 週次タイムバジェット（平日30分／休日3時間）
| 枠 | 時間 | 使うこと（オーナー） |
|---|---|---|
| 平日 月〜金 | 各30分 | **AIが用意した今日のXを1本投稿＋15〜20分 誠実な返信/交流**。これだけ。コードは触らない（細切れ時間は人的交流に集中） |
| 土 | 3時間 | ①来週分のX(10〜14本)をAIドラフトから personalize して**予約投稿**（90分）②Note 1本を仕上げて公開（60分）③受信対応（30分） |
| 日 | 3時間 | ①開発/運用枠：AIが用意したコード/手順を**適用・ビルド・デプロイ/申請**（90分）②KPIレビュー＋私と来週計画（60分）③予備（30分） |

合計 ≈ 週8.5時間にフィット。**平日は"人間の声"、週末は"仕込みと前進"** の二層構造。

## 4. フェーズ計画（時間制約版）
| フェーズ | 主眼 | オーナー時間の使い所 | AIチーム |
|---|---|---|---|
| **P0 即時** | 出荷の門を開ける | **B2/B3(push/署名)解消の確認**・Apple有効化待ち | Web結線・ペイウォール・年額をドラフト実装で待機 |
| **P1 Web ソフトローンチ** | 最速で初課金＆学習 | deploy承認・X種まき開始 | Stripe結線/計測/ペイウォールを納品、内容運用伴走 |
| **P2 ネイティブ並行ビルド** | 本命チャネル準備 | 週末にビルド・ストア申請（runbook通り） | Capacitor/IAP/申請文を完成形で供給 |
| **P3 ストア公開＋拡大** | KGIへ | 公開ボタン・PR配信・継続運用 | ASO/PR/紹介/リテンション施策を供給 |
| **〜12月** | **継続150人** | 週次の投稿・対応・意思決定の継続 | 毎週KPIを見て翌週施策を最適化 |

## 5. 自動化・テコ入れ（オーナー時間を作る）
- X：**予約投稿ツール**（Typefully等）で週末に1週間分を仕込む。AIが本文ドラフト→オーナーが自分の言葉に微修正。
- Note：AIが構成＋本文ドラフト→オーナーは実体験で味付けして公開。
- CS/レビュー対応：AIがテンプレ＋FAQ。オーナーは固有case のみ人力。
- 計測：PostHog自動ダッシュボード→日曜の60分レビューに集約。
- 開発：AIがコード・SQL・runbookを完成形で。オーナーは適用とデプロイのみ。

## 6. やらないことリスト（絞る＝時間を守る）
- 平日のコーディング（細切れで非効率）。
- 完璧主義のデザイン磨き（ローンチ品質に達したら止める）。
- 多チャネル同時展開（X＋Noteの2本に集中。Instagram/TikTok等は当面やらない）。
- 有料広告（LTV>CAC確認まで）。フリーミアム・トライアル（決定済み：やらない）。
- 機能追加（コア完成済。ローンチ後は計測で必要なものだけ）。

## 7. 正直な実現可能性評価
- **マーケ（KGIの主動力）は週8.5時間でも"バッチ＋AIドラフト"で継続可能** ← ここが回ればKGIは射程。
- **最大リスク＝ネイティブ審査がオーナー時間を食い潰すこと** → §2のWeb先行で回避。
- **次のリスク＝継続性**（週8.5時間を半年続けられるか）。だから"手を動かさない"設計と自動化が必須。燃え尽きたら終わる。
- 総括：**「個人の時間」では足りない。だが「AIチーム＋自動化＋絞る」を足せば、週8.5時間は十分KGIに届く設計に変えられる。**鍵は、オーナーが"作業者"でなく"意思決定者と顔"に徹すること。
