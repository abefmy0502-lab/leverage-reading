# 発信者・読書会・講座への連絡（本要約の YouTube・Voicy・読書会・読書術の講座）

> 2026-10-08 作成。正は `company/marketing-strategy-2026-11.md` §5-5・§8。連絡する日：**11/4（水）〜11/6（金）**（公開の 2 週前。返事を待って、公開日〜12/16 の創業メンバー期間に紹介してもらう）。
> 渡すのは **App Store のオファーコード（プランの無料期間）だけ**。現金・物品は渡さない。

## 0. 守ること（全員に共通）

1. **コードを渡した相手の紹介は「広告」**（景品表示法のステマ規制・2023/10〜）。投稿・動画・番組の**最初に目に入る位置に「PR」**と、「Orime から無料の利用コードの提供を受けています」を入れてもらう。こちらから**最初の連絡の時点で**お願いする（`brand-guardrails.md` 2）。PR 表記が無理な方には、コードを渡さない。
2. **紹介してもらった投稿・動画・番組を、Orime の LP・App Store・note・X の固定ポストなどに転載しない**（転載で措置命令の例がある＝大正製薬 2024・ロート製薬 2025）。リポストで広めるのも控える（必要なら、PR 表記が見える形の引用だけ）。
3. **言ってほしいことを指定しない**。渡すのは「事実のまとめ」（下の §6）だけ。台本・文言・評価の指定はしない。良くないと思ったことも、そのまま言ってもらってよい。
4. **App Store のレビュー・評価を頼まない**。視聴者・参加者にレビューを頼んでもらうこともしない（審査 5.6・3.2.2）。
5. テンプレートは下書き。**その方の動画・番組・会を実際に見て、固有の一文を足すまで送らない**（同 5）。足せない相手には送らない。
6. 数字（登録者数など）を相手に向けて持ち出さない・持ち上げすぎない。断られたら追わない（1 通まで・催促は 1 回だけ）。

## 2. オファーコードの作り方（オーナー・App Store Connect）

1. 収益化 → サブスクリプション → **月額プラン（`orime_monthly`）** → オファーコード → 作成。
   - 対象：**新規の購読者**／国：日本／種類：**無料・1 か月**（参加者向け）
   - **カスタムコード**を相手ごとに 1 つ（例 `ORIME-NEKOMACHI`・`ORIME-BOOKCAFE`。相手の会・番組の名前を使うときは本人の了解を取る）。使える回数の上限は **200**・有効期限 **2026-12-31**。
2. 相手本人が先に使ってみるための**使い切りのコード**（1 回だけ・3 か月無料）を 1 つずつ。
3. コードは**公開日（11/17）から使える**。引き換えの URL：`https://apps.apple.com/redeem?ctx=offercodes&id=【App ID】&code=【コード】`
   - アプリの中の「コードを使う」は**まだ無い**（戦略 §6 の 6・公開前に作る予定）。できるまでは、上の URL か App Store アプリの「アカウント → ギフトカードまたはコードを使う」で引き換える。
4. 1 つの国・1 四半期に 100 万回まで（十分）。
5. **原価の目安**：無料の 1 か月でも AI の原価はかかる（1 人 月 約 ¥79・上限 ¥240）。200 回 × ¥79 ≈ ¥16,000 が 1 つのコードの最大の目安。全部で 5 件なら最大 約 ¥80,000（戦略 §8 の「現金 0 円」の外の費用）。始めは 3 件に絞り、引き換えが伸びたら回数を足す。

創業メンバーとの関係：コードでプランを始めた方も、期間中（〜12/16）なら創業メンバー（「プランを始めた全員」）。年額プランの 1 年目 ¥9,800 とは別の話なので、紹介のときは混ぜない。

## 7. 最優先：仕事の考え方の note メンバーシップの書き手（2026-10-08 追加）

> オーナーが読んで学びになった記事の書き手。連絡は **11/4（水）にいちばん先に**（note 03 の公開 11/10 より前に、出典の載せ方の了解ももらうため）。§0 の 6 つの決まりはそのまま守る。

### 7-1. 埋める欄（オーナー）

| 欄 | 中身 |
|---|---|
| 書き手の名前 | 【書き手の名前】 |
| 読んだ記事の題と URL | 【記事の題】【URL】 |
| メンバーシップの名前と URL | 【メンバーシップの名前】【URL】 |
| 連絡の窓口 | 【note のお問い合わせ／X の DM／メール：記事やプロフィールに書かれている窓口だけを使う】 |
| 記事を読んで自分が実際にやったこと | 【例「読書メモに『この本の人は何を見る人か』を一行足すようにした」。やっていなければ、連絡文のその文を消す】 |

### 7-2. なぜ合うか

- **読者が重なる**：仕事の考え方を月額のメンバーシップで学んでいる会社員＝戦略 §1-1 の A・C（本を読み、記録もしているのに、使えていない人）。オーナーが見た時点の表示で購読者 2,900 名以上・記事 280 本以上（【連絡の前に表示を確かめる】・**連絡文や公開物には書かない**＝§0 の 6）。
- **主張が同じ向き**：記事は、視点を増やす方法の 1 つ目に「本を読んで、著者の視点を自分の中にためる（メモを取る）」を挙げている。Orime の一番の価値「読むほど、自分だけの相談相手が育つ」と、ほぼ同じことを別の言葉で言っている。
- **機能がつながる**：相談の答えのあとのチップ「ほかの本の視点で」「2 つ上の立場なら」「前と後ろの工程から」（作る予定）は、記事の視点・視座・視野にそのまま対応する。読者が記事で学んだことを、自分の読書メモで試せる。
- **型が合う**：講座との提携（§1 の 2）と同じ型。メンバーシップの読者向けのコードは、記事で学んだ「その後」に使ってもらう形にできる。
- 合わない点（正直に）：書き手は「本を読むこと」を勧めていても、アプリの紹介をする方とは限らない。紹介が無くても、記事に学んだことを note 03 で出典つきで紹介できれば十分、と考える。
