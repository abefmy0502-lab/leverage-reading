## 1. ファネルと「生命線」


## 2. 7月の成果目標（正直な現実線）

**前提：母数が小さい初期（M1フォロワー300〜500想定）× ハードペイウォール¥1,480（7日間無料体験つき）。** ロードマップの「7月25〜40継続」は本来ストア公開＋PR＋Product Hunt＋種まき刈り取り前提の数字で、7/27リリース（7月は実質5日）＋小さなオーガニック母数では届きにくい。**過大約束しない。**

| 指標 | 7月の現実線 | 位置づけ |
|---|---|---|
| 🎯 有料課金者（北極星） | **1〜15人** | KGI(2026=約100継続)への最初の一歩。0→1が最重要 |
| LPクリック（SNS→LP） | 週50〜150 | 先行指標。コンテンツの引きを測る |
| signup開始 | 月30〜80 | LPの転換力を測る |
| checkout開始→完了 | 開始の30〜60% | Paywallの説得力を測る |
| Xフォロワー | 〜500 | 土台（直接の成果ではない） |

> **0→1（最初の有料1人）を7月の絶対達成ラインに置く。** ここを超えると「実在の声」が得られ、社会的証明→転換の好循環が回り始める。数十人は8月以降のASO/口コミ加速で取りに行く。

## 3. 「売れるSNS」へのコンテンツ磨き（5本柱は維持・転換設計を上乗せ）

既存5本柱（①実体験②読書Tips③build in public④本の学び⑤交流）は維持。その上に**直接課金を効かせる4つの転換装置**を仕込む：

1. **価値実演（買う前に効果が分かる）** — 「マイ読書脳に"決断の判断軸は?"と聞いたら、3年前に読んだ本のメモから自分の言葉で返ってきた」等、**自分のメモ→AI回答の実画面**を見せる。抽象論でなく実演。これが¥1,480の根拠になる。
2. **自然な"買える先"提示（週2〜3回）** — 毎投稿で売らない。週の何回かで「Orime、もう使えます（月¥1,480・7日間無料・10秒解約）」を**さらっと一行**。固定ポストとプロフィールリンクは常時"今日から使える"に。
3. **Readee難民の時限刈り取り** — 「サ終しない・データを大事にする有料アプリ」を名乗る受け皿宣言＋CSV移行の安心。3月終了の余波が残る7月が最後の好機。`#Readee` 関連の会話に人として入る。
4. **社会的証明の獲得を最優先タスク化** — 初期ユーザーの一言・スクショ・"使ってみた"を**引用RT/許可を取って掲載**。最初の数人の声が次の転換を生む。LPの社会的証明枠（§5）に流し込む。

**鉄則（不変）：** AIっぽい量産をしない。宣伝1:価値9。声と対話は人間（fumiya）。価値先・売り後。

## 5. LP転換最適化ワークストリーム（CEO配下で実装・env非依存）

現状LPは強いが、**直接課金の転換率を上げる**ために磨く（push解放前でもローカル実装可）：

1. **社会的証明枠の準備（最重要）** — 現状 trust-bar はコメントアウト（嘘の数字を入れない正しい判断）。**実ユーザーの声が出た瞬間に差し込める枠**を用意（1〜2件でも"実在の声"は効く）。実数ゼロのうちは出さない。
2. **signup→Paywall の摩擦最小化監査** — LPの「始める」→ `/`（AuthScreen）→ Paywall→IAP購入シート（RevenueCat）の導線が、初見でも迷わず・最短で課金に到達するか実機相当で確認。離脱箇所を潰す。
3. **直接課金のための一貫性監査** — LPの全主張が製品と一致しているか（✅"🔥連続達成日数"は実在を確認済）。誇大表現の景表法/Apple準拠は既にde-risk済（"活かしきれていないかもしれない金額（参考）"）。
4. **UTM/簡易計測** — SNS流入を見分ける（§7）。

> 実装は §0 の方針（既存挙動非破壊・思想厳守）で、push解放後に即出せる状態で積む。

## 6. ローンチ日シーケンス（7/27・App Store で買える化が前提）

1. **固定ポスト差し替え**：原体験スレッドの最後を「公開しました。今日から使えます（月¥1,480・7日間無料・10秒解約・データ残る）」＋LPリンクに。
2. **ローンチ告知スレッド**：なぜ作ったか→何ができるか→正直な現在地（"精度はまだ発展途上、でも自分のメモが答えになる感覚は本物"）→価格の理由（なぜ無料にせず¥1,480にしたか＝記録止まりにしない覚悟）→リンク。
3. **Readee受け皿宣言**：「サ終しない・データを大事にする有料アプリです」＋移行の安心。
4. **Note公開**：「3年で200冊読んで、ほぼ忘れた。だから読書アプリを自作した話」→ X で一言＋リンク。
5. **build in public の応援者に拡散依頼**（売り込みでなく"見届けてくれた人へ報告"）。
6. ローンチ実況（リアルタイムの素直な反応）。

## 7. 計測（成果＝有料課金者数を測る土台）

直接課金を改善するには**ファネルの各段が見える**必要がある：
- **LP→App Store→install→signup→購入開始→完了** を analytics基盤（実装済 `analytics.js`）＋ RevenueCat／App Store Connect ＋ 簡易UTM で追う。
- 毎週見る：LPクリック／install数／signup率／購入開始率／完了率／**課金者数**。
- 落ち所（最も離脱する段）を1つずつ潰す＝直接課金の磨きの本体。
> 注：本格計測（PostHog等）は法務前提（プライバシーポリシーへ委託先追記）が通ってから。当面は自前 analytics＋RevenueCat／App Store Connect ダッシュボードで足りる。

## 8. 🚦 クリティカルパス（正直に・成果の前提条件）

**App Storeで"実際に買える"には、コードの外の前提が要る。これが無いと7/27に売上ゼロ。最優先で元帥に依頼：**

1. **push 403 解放 → デプロイ** — 積み上げた成果（課金基盤含む）を本番に出せて初めて"買える"。**最大のボトルネック**。
2. **IAP 本番設定** — App Store Connect の IAP商品（月¥1,480/年¥12,800・7日間無料トライアル）登録／RevenueCat Offering・Webhook（`revenuecat-webhook.js`）疎通／TestFlight でテスト課金確認。
3. **独自ドメイン/公開URL** — SNSから送る先（LP）の安定URL。
4. **（任意）法務のApp内課金整合の最終確認** — 規約/特商法は¥1,480反映済。最終目視。

> 1〜3が揃わない場合、7/27は「直接課金」ができない＝この計画は回らない。その場合の代替は「買える化までは価値実演で土台を作り、買える化と同時にローンチ告知で刈り取り」。**まず1〜3の状況を確認したい。**
