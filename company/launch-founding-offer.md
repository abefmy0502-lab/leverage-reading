# 🌱 創業メンバー価格 — オーナーの作業手順（App Store Connect・Vercel・確認）

> 2026-10-02 オーナー承認。11 月の公開に合わせて、**公開から 30 日間**だけ、年額プランの **1 年目を ¥9,800**（2 年目から通常の ¥12,800）にする。
> **創業メンバー**＝期間中に**プランを始めた全員**（月額・年額どちらでも・7 日間無料で始めた方も・人数の上限なし・2026-10-02 コーディネーター裁定）。特典は **開発者への直接の窓口**（要望を優先して読む）と **次に作る機能への投票**。**¥9,800 は年額プランだけ**。
> **「先着 300 人」とはどこにも書かない**（App Store の初回特典は人数で止められない。守れない希少性の表示は景表法のリスク）。

## 0. 仕組み（30 秒で）

| どこ | 何が決める | 期間が終わると |
|---|---|---|
| 実際に払う金額 | **App Store**（年額プランの初回特典＝先払い・1 年・¥9,800） | App Store Connect の終了日で止まる |
| アプリの有料プランの画面の金額 | ストアの値（`src/lib/planOffers.js` が introPrice を読む） | ストアに無くなれば通常の価格に戻る |
| アプリの「創業メンバー価格」という呼び名 | ストアに初回価格がある **かつ** env の期間中 | 終わる日の翌 0 時（日本時間）で自動で消える |
| アプリの特典の 1 行（「…までにプランを始めた方は、月額・年額どちらでも創業メンバーです」） | env の期間中（値段の約束ではないので、ストアの初回価格が無い人にも出す） | 同上 |
| LP（紹介ページ）の節・印・料金・FAQ | env（`VITE_FOUNDING_OFFER` / `_END` / `_PRICE_LABEL`） | 終わる日の翌 0 時（日本時間）で自動で消える |

- App Store の初回特典は **1 つの商品・1 つの国に 1 つだけ**。期間中、年額プランの初回特典は「1 年目 ¥9,800」になるので、**年額の 7 日間無料は付かない**。月額プランは 7 日間無料のまま。
- 初回特典は **同じサブスクのグループで 1 つの Apple ID に 1 回**。月額の 7 日間無料を使った人は、年額の 1 年目 ¥9,800 を使えない（アプリと LP に書いてある）。
- RevenueCat の `period_type` は 7 日間無料が `TRIAL`、1 年目 ¥9,800 が `INTRO`。2026-10-02 から `intro` は **有料**として数える（毎月 800 トークン・設定は「年額プラン」）。

## 1. App Store Connect（公開の数日前までに）

1. App Store Connect →（Orime）→ **収益化 → サブスクリプション** → サブスクリプショングループ → **年額プラン（`orime_annual`）** を開く。
2. いまの **7 日間無料（お試しオファー＝無料）** の **日本** の終了日を、公開日の前日にする（初回特典は国ごとに同時に 1 つだけ）。
3. 「サブスクリプション価格」の横の **＋ → お試しオファーを作成（Create Introductory Offer）**。
   - **国または地域**: 日本（ほかの国は今までどおり）
   - **開始日**: 公開日（例 2026-11-16）
   - **終了日**: LP に書く最後の日の **翌日**（例 LP が 12月15日まで → 2026-12-16）。App Store の日付の区切りは日本時間とずれることがあるので、LP の約束より短くならないよう 1 日余らせる（長い分にはお客様の得になるだけ）。画面に出るタイムゾーンを必ず確かめる。
   - **種類**: **前払い（Pay up front）**
   - **期間**: **1 年**
   - **価格**: **¥9,800**
4. 年額の **7 日間無料を戻す予約**: 同じ手順で「無料・1 週間」のお試しオファーを、開始日＝上の終了日の翌日で作る（重ならない日付なら予約できる。できなければ終了日の翌日に作る）。
5. **月額プラン（`orime_monthly`）は触らない**（7 日間無料のまま）。
6. 商品の説明（表示名・説明）は `company/app-store-listing.md` のまま。審査メモに「年額プランは公開から 30 日間、初回特典（前払い 1 年 ¥9,800）」と 1 行足す。

## 2. Vercel（LP）と iOS アプリのビルド

| 変数 | 値の例 | 意味 |
|---|---|---|
| `VITE_FOUNDING_OFFER` | `on` | 出す（ほかの値・未設定は出さない） |
| `VITE_FOUNDING_OFFER_END` | `2026-12-15` | LP に書く最後の日（日本時間・この日の 23:59 まで）。無い・読めないと出さない |
| `VITE_FOUNDING_PRICE_LABEL` | （未設定） | LP の値段の書き方。既定「1 年目 ¥9,800」 |

- Vercel の Production に入れて、**公開日に出し直す**（VITE_ はビルドのときに埋め込まれる）。
- **iOS アプリのビルドにも同じ値を入れる**（有料プランの画面の「創業メンバー価格」の呼び名と特典の 1 行に使う）。入れ忘れても、金額はストアどおり「1 年目 ¥9,800」と出る（呼び名が出ないだけ）。
- 終わる日を過ぎると LP もアプリも自動で通常の表示に戻る。落ち着いたら `VITE_FOUNDING_OFFER` を消して出し直す（任意）。

## 3. 確かめる（TestFlight・サンドボックスのアカウント）

1. 有料プランの画面: 年額の行が「1 年目 ¥9,800／2 年目から ¥12,800」・「創業メンバー価格」・年額に 7 日間無料が出ない・月額の行に「最初の 7 日間は無料」・選択肢の下に「…までにプランを始めた方は、月額・年額どちらでも創業メンバーです」。
2. 下の欄が「1 年目 ¥9,800、2 年目から 年額 ¥12,800 で自動更新」・ボタンが「年額プランで始める」。
3. 年額を買う → Supabase の `subscriptions.period_type` が `intro`・設定の「プラン」が「年額プラン」・相談の上部が「今月の残り 800 トークン」。
4. 別のサンドボックスのアカウントで月額の 7 日間無料を始めてから年額を見る → 年額は通常の ¥12,800（初回特典を使えない）。
5. お試しモードで見た目だけ確かめるとき: `npm run demo` → `/?demo=paywall&native=1&founding=on&trial=7日間無料`（`founding=store`＝ストアだけ・`env`＝期間だけ）、LP は `/?demo=auth&founding=on`。

## 4. 公開後・期間のあと

- **Supabase**: `supabase_admin_members_tasks.sql` をもう一度流す（運営ダッシュボードの会員内訳で `intro` を有料に数える・2026-10-02 更新）。
- **運営ダッシュボードの MRR**: 同じ SQL の `admin_revenue` が `founding`（有料のうち `period_type='intro'` の人数）を返し、ダッシュボードはその人数だけ ¥9,800 ÷ 12（≈ ¥817）で数える（2 年目の更新で `normal` に戻ると通常の額）。
- **創業メンバーの一覧**（特典の連絡用・service_role の SQL Editor）。**期間中にプランを始めた全員**（月額・年額・7 日間無料で始めた人も）。日付は公開日〜終わる日の翌日（日本時間の 0 時＝前日 15:00 UTC に合わせて調整）。

```sql
-- ① 契約の履歴（supabase_subscription_events.sql）があるとき＝いちばん確か。最初にプランを始めた時刻で決める
--    （7 日間無料のうちにやめた人も「始めた」に入る。status・期間の種類を見て、特典を送るかはオーナーが決める）
with first_start as (
  select e.user_id, min(e.event_at) as started_at
  from subscription_events e
  where coalesce(e.environment, 'production') <> 'sandbox'
  group by e.user_id
)
select f.user_id, u.email, f.started_at, s.status, s.price_id, s.period_type
from first_start f
join auth.users u on u.id = f.user_id
left join subscriptions s on s.user_id = f.user_id
where f.started_at >= '2026-11-15 15:00+00' and f.started_at < '2026-12-15 15:00+00'  -- 11/16 0:00〜12/16 0:00（日本時間）
  and f.user_id not in (select user_id from app_admins)
order by f.started_at;

-- ② 履歴の表が無いとき: subscriptions の行を作った時刻（1 人 1 行・最初の契約で作られる）で代わりに見る
select s.user_id, u.email, s.created_at, s.status, s.price_id, s.period_type
from subscriptions s join auth.users u on u.id = s.user_id
where s.created_at >= '2026-11-15 15:00+00' and s.created_at < '2026-12-15 15:00+00'
  and s.user_id not in (select user_id from app_admins)
order by s.created_at;
```

- 特典の「直接の窓口」「機能への投票」の場所（メール・フォームなど）はオーナーが決めて、上の一覧の方に知らせる（アプリの中にはまだ専用の画面は無い）。
- 期間のあとは **App Store 側が 2 年目から ¥12,800 で自動更新**する（アプリ側の作業は無い）。

## 5. 別の案: 「先着 300 人」にしたくなったら（オファーコード）

人数で止めたいときは、初回特典ではなく **オファーコード** を使う（コードの入力が要る）。

1. App Store Connect → 年額プラン → **オファーコード → 作成**。
   - 対象: 新規の購読者 / 国: 日本 / 種類: **前払い・1 年・¥9,800**
   - **カスタムコード**（例 `ORIME300`）を作り、**使える回数の上限を 300** にする（有効期限も設定）。または 1 回きりのコードを 300 個作って配る。
2. 配り方: App Store の引き換え用の URL（`https://apps.apple.com/redeem?ctx=offercodes&id=<App ID>&code=<コード>`）を LP やメールに置く。アプリの中で入れてもらうには「コードを使う」ボタン（RevenueCat の `presentCodeRedemptionSheet`）が要る（**未実装**）。
3. このときだけ LP に「先着 300 人」と書ける（App Store が 300 回で止めるので、表示と実際が一致する）。初回特典（上の 1.）と同時に出すかは、オーナーが決める（両方出すと LP の説明が複雑になる）。
4. アプリの有料プランの画面は、オファーコードの価格を事前には表示しない（引き換えたときに App Store のシートで金額が出る）。

## 6. 文言のルール（LP・ストア・SNS）

- 書く: 「公開から 30 日間・年額プランの 1 年目が ¥9,800（2 年目から ¥12,800）」「期間中にプランを始めた方は、月額・年額どちらでも創業メンバー」「◯月◯日まで」「人数の上限はありません」。
- 書かない: 「先着 300 人」「残りわずか」「今だけ」の煽り・期限の無い「期間限定」。通常価格（¥12,800）は実際に売っている価格なので「2 年目から ¥12,800」は書いてよい。
- 年額に「7 日間無料」と書かない（期間中は月額だけ）。用語は CLAUDE.md の GLOSSARY（創業メンバー価格・無料プラン（ずっと無料）・7 日間無料）。
