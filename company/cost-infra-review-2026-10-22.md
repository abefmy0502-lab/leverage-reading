## 2. 見送ったもの（理由つき・次の候補）

| 候補 | 見込み | 見送った理由 |
|---|---|---|
| 答えの末尾の REFS（画面に出さない出力・¥0.07〜0.1／回＝¥3〜4／人・月） | 相談の原価の 1 割 | 「根拠を見る」「あなたのメモ N 件から答えました」が REFS を読む。【参照した本のメモ】から組み立て直す道はあるが、根拠の件数が減らないかを 1〜2 週ログで見てから |
| 質問に近いメモ（extra）を会話中は固定して印を付ける（メモ 9,000 字超の人・¥2〜6／人・月） | 重い人だけ | 返事の言葉にだけ当たる周辺のメモが拾われなくなる＝**質に触る**。関係するメモの一致率を測ってから |
| 相談の指示文を 15% 短く（裁定メモの削除・¥0.8／人・月）・メモの見出しの略記（¥2〜3／人・月） | 小 | 指示文は答えの形・根拠・語り口の決まりそのもの。変えると 1 時間のキャッシュが一度冷える。やるなら利用の少ない時間に、評価とセットで |
| この本で学べることを ISBN ごとに全員で使う（¥0.5／人・月） | 小 | 入力に「この人が得たいこと」が入り仮説の例がそれに寄る＝共有すると個別性が落ちる。得たいことが空の本だけなら可能だが、表・RPC・上限の手間に見合わない |
| 起動の books クエリから AI の長文の列（読書計画シート・解析・学べること・まとめ）を外す | 転送量 − | 相談の材料（`gatherKnowledge`）と本の詳細がその列を使う。外すと相談の根拠が減る経路があるので、本の詳細と相談の両方を「開いたときに取る」形に直してからでないと**質に触る** |
| 契約の確認 → 本の読み込みの直列を並列に（起動 RTT −1） | 体感 良 | `AuthedApp` の描画の順番を変える大きな手術。次の UI の節目で |
| `App.jsx`（7,800 行・490KB）から本の詳細を切り出す（起動 JS −1〜2 割） | 体感 良 | 同上 |
| 404 のやり直し先が Sonnet 4.6（Haiku の 3 倍） | 事故のとき | Haiku 自身が 404 になる日に相談を止めるより、一時的に 3 倍で動かすほうが利用者に優しい。警告ログは出る |
| `max_tokens` を下げる・`warm` の頻度・キャッシュの長さ | — | 原価は実額で精算されるので下げても 1 円も減らず、途中で切れる危険だけ増える。warm の損得は計算どおり |
