# note の説明書の連載（2026-11-25）

> オーナー「note の役割は、世の中に詳細な機能を伝えること。そのままユーザーには説明書として使いたい。note は AIO に強い」。
> アプリのヘルプは「使い方を短く（1 項目 3 行まで）」。note は「くわしい説明書」。役割を分ける。

## どこに出るか（もう作ってある）

| 場所 | 出し方 |
|---|---|
| アプリのヘルプ（？）のいちばん下 | 「この画面をくわしく読む（note）」（その画面の記事があるとき）／「くわしい使い方を読む（note）」（無ければ note のトップ） |
| 設定 › アプリ・サポート | 「くわしい使い方（note）」（note のトップ） |
| LP のフッター | 「使い方（note）」 |
| LP の JSON-LD | `sameAs` に note のトップ（AI の検索・回答エンジンが orime と note を結びつける） |
| `/llms.txt` | orime の説明＋「機能ごとのくわしい説明（note）」の一覧（AI 向けの説明書の目次） |

どれも URL が空のあいだは出ない。

## URL の入れ方（オーナー・1 分）

1. `public/note-links.json` を開く
2. `home` に note のトップ（例 `https://note.com/orime_app`）を入れる
3. 記事を出したら `guides` に「ヘルプのキー: 記事の URL」を足す（下の表のキー）
4. main へ push（Claude に「note の URL を入れて」と言えば代わりにやる）

- Web はその公開ですぐ替わる。**iPhone のアプリも出し直し不要**（アプリは本番サイトの `note-links.json` を読む・読めなければ前に読んだ控え）。
- `note.com` の https 以外は捨てる（ほかのサイトへは飛ばさない）。

## 連載の並び（ヘルプのキー → 記事の題）

いちばんの価値（読むほど相談相手が育つ）に近い順。1 本目は「全体の地図」、2 本目から機能ごと。

| 順 | キー | 記事の題（案） | 中身 |
|---|---|---|---|
| 0 | （home） | orime の説明書：はじめに | 何のアプリか・全体の地図・この連載の目次（各記事へのリンク） |
| 1 | `myBookBrain` | 相談：自分のメモから答える AI | 答えのもと（メモ・読書準備・歩みだけ）・根拠を見る・本と話す／著者と話す・聞き返しは 2 回まで・無料プランのトークン |
| 2 | `memoEditor` | メモの書き方：一行でいい | 一行メモ・ページ番号・写真から書き起こし・この本のまとめ・合いそうなタグ |
| 3 | `bookList` | 本を入れる：検索・バーコード・本棚の写真・引越し | 4 つの状態・ブクログ／読書メーター／Kindle／Goodreads／書名の一覧の取り込み手順（画面つき） |
| 4 | `actionList` | 行動：読んだら一歩 | 相談から行動へ・期限・繰り返し・完了 |
| 5 | `review` | 振り返り：忘れた頃に戻ってくる | 思い出しカード・月ごとのメモ・読書の記録・分野 |
| 6 | `aiAdvisor` | AI 選書：実在する本だけをすすめる | 聞き取り・書店で確かめる・本棚へ |
| 7 | `bookDetailBefore` | 積読と読書計画シート | この本で学べること・読書計画シート・得たいこと／仮説 |
| 8 | `bookDetailReading` | 読書中：集中モードと読書の時間 | 読む・タイマー／計測・メモ |
| 9 | `bookDetailDone` | 読了：3 つの問いと答え合わせ | 読了の問い・読む前に書いたこと・写真で共有 |
| 10 | `billing` | 無料プランとプラン・トークン | 無料でできること・トークンの目安・プランで深まること |

キーの一覧の正は `scripts/llmsTxt.mjs` の `GUIDE_TITLES`（テストでヘルプのキーと一致を確かめる）。

## AIO で読まれる書き方（1 本ごとの型）

1. **最初の 3 行で「何ができるか」を言い切る**（AI の回答エンジンは冒頭を引用しやすい）。例「orime の相談は、自分が残した読書メモだけを根拠に AI が答える機能です。」
2. **見出しは利用者の問いの形**（「無料でどこまで使えますか？」「Kindle のハイライトは取り込めますか？」）。答えは見出しのすぐ下に 1〜2 文。
3. **言葉はアプリと同じ**（GLOSSARY: 相談・行動・積読・分野・フォルダ・トークン・7 日間無料）。同じものを別の名前で呼ばない。
4. **実際の画面を 1〜3 枚**（`npm run demo` → `npm run ui:shots`。サンプルの本・メモで撮る）。
5. **数字は変わるものを書かない**（値段・トークンの量は「App Store の表示が正」「アプリの設定で見られます」）。書くときは日付を添える。
6. **最後に LP へのリンク 1 つ**（`https://orime.vercel.app/lp?utm_source=note&utm_medium=manual&utm_campaign=<キー>`）と、連載の目次（home の記事）へのリンク。
7. 書いた日と、アプリの版（設定の「新しくなったこと」の日付）を末尾に。機能が変わったら記事も直す（`src/lib/releaseNotes.js` に項目を足したら、該当の記事の見直しを ops のやることに 1 つ）。
