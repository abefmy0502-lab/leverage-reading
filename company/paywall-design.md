## 0. 設計の狙い
- Orimeの核価値（**想起・マイ読書脳**）は"使って効く"＝初日課金と最も相性が悪い。**だから課金を迫る前に価値を"見せる"**。これが install→課金を上げる最大レバー。
- 全機能有料（無料枠なし・7日間無料トライアルあり）。アプリは**無料DL＋ハードペイウォール**。

## 1. 初回起動フロー（未課金）
```
起動 → ①ようこそ(1枚) → ②価値プレビュー(2〜3枚・操作不要のデモ) → ③ペイウォール → 購入 → ④課金後オンボーディング
```
- **①ようこそ**：「読んだのに、覚えてない——をやめる読書アプリ Orime」。1枚、すぐ次へ。
- **②価値プレビュー（肝・"見せる"）**：実データ入力は求めず、サンプルで体感させる。
  - プレビューA：🔄 **想起カード**のサンプル（「3ヶ月前のあなたのメモ」が"ふっ"と表示される動き）。コピー「気づきは、忘れた頃に戻ってくる。」
  - プレビューB：🧠 **マイ読書脳**のデモ（質問→自分のメモを根拠にした回答＋参照本がアニメで出る）。コピー「あなたのメモが、答えになる。」
  - （任意C）📇 一行メモの軽さ。
- **③ペイウォール**：下記§2。
- スキップ導線：プレビューは「スキップ」可だが、その先は必ずペイウォールに到達（全機能有料のため）。

## 2. ペイウォール画面（§Apple 3.1.2 必須開示を満たす）
**構成（上→下）**
1. ヘッダーコピー：**「読みっぱなしを、やめる。」** ＋ サブ「Orimeの全機能を、いつでも。」
2. ベネフィット3点（アイコン＋一行）：
   - 🔄 振り返り・ランダム想起で**気づきを呼び戻す**
   - 🧠 自分のメモを根拠に**AIが答える**（マイ読書脳）
   - 🎯 1冊から**行動に変える**（AI選書・行動リスト）
3. **プラン選択（年額を主役）**：
   - ⭐**年額 ¥12,800/年**（バッジ「いちばんお得・約28%オフ」／補助「月あたり約¥1,066」）← デフォルト選択・大きく
   - 月額 ¥1,480/月（控えめに）
4. 主CTA：**「Orimeを始める」**（選択中プランで購入）
5. **復元**：「購入を復元」リンク（Apple必須）
6. **必須開示（小さめ・但し明確に）**：
   - 「サブスクリプションは自動更新されます。期間終了の24時間以上前に解約しない限り、同額で更新されます。解約は App Store の管理画面から。」
   - 「[利用規約] ・ [プライバシーポリシー]」リンク
7. トーン：静か・余白・誠実（煽らない）。カウントダウン/偽の割引/不安喚起は使わない（ダークパターン回避＝返金率・審査リスク対策）。

**技術**
- RevenueCat の **Offering**（2 Package：`annual`＝¥12,800 / `monthly`＝¥1,480）を表示。購入は `Purchases.purchasePackage()`。
- 購入前に `Purchases.logIn(user.id)`（Supabase user.id を app_user_id に）。成功で `customerInfo.entitlements.active` を即反映＋webhookが `subscriptions` 更新 → `useSubscription().refresh()`（webhook遅延に備え数秒リトライ）。

## 3. アプリ全体ゲート（モデルA＝全機能有料）
- `App.jsx` のルーティング最外で `useSubscription()` を呼び、`user && !subLoading && !isActive` のとき**全画面をペイウォールで覆う**（本棚/振り返り/AIの手前で return ガード）。
- `subLoading` 中はスピナー。`subscriptions` テーブル未適用時は schema-fallback（isActiveでブロックしすぎない設計に注意：未適用＝判定不能なら"ローンチ前の安全側"を選ぶ。ローンチ時は必ず適用）。
- Checkout復帰（`?checkout`／IAP完了）後は `refresh()`。

## 4. 課金後オンボーディング（初月チャーン対策＝最重要リテンションKPI）
購入直後に**3ステップのガイド完走**を促す（"価値を一度も体験せず放置"を防ぐ）：
1. 「最初の1冊を登録」→ 検索 or 手動で1冊。
2. 「読みながら、一行メモ」→ 1メモ作成（Aha到達）。
3. 「マイ読書脳に1問だけ聞いてみる」→ 自分のメモ（少なくてもOK）に対するAI回答を体験。
- 完走率を計測（PostHog `onboarding_completed`）。離脱ステップを改善。

## 5. 想起リマインド（リテンションの本丸）
- プッシュ/メールで「あの本の、あの気づき」を定期想起（プロダクト価値＝リテンション機構）。頻度は控えめ・オプトアウト可。実装はローンチ後フェーズでも可だが、設計はここに記録。

## 6. 解約フロー内オファー（ストア規約の範囲で）
- アプリ内の「サブスク管理」からストアの解約画面へ誘導しつつ、**直前に「月額→年額の乗り換え割」or「一時停止」**を提示（解約抑止）。Apple/Googleの規約内で。

## 7. 計測（PostHog 課金ファネル）
`paywall_viewed` → `plan_selected(annual|monthly)` → `purchase_started` → `subscription_activated(plan, price)` ／ `restore_clicked` ／ `paywall_dismissed` ／ `onboarding_step(1..3)` ／ `onboarding_completed`。
- 北極星の手前指標：**install→paywall_viewed→purchase の各通過率**を毎日。

## 8. 実装タスク（ネイティブ化後・エンジニア）
1. RevenueCat Offering/Package 表示＋購入＋復元（`@revenuecat/purchases-capacitor`）。
2. 価値プレビュー2〜3枚（サンプルデータ・操作不要）。
3. `App.jsx` の全体ゲート（`useSubscription` 連携）。
4. 課金後オンボーディング3ステップ。
5. PostHog イベント（§7）。
6. AccountSettings に「プラン状況／購入を復元／サブスク管理（ストアへ）」。
7. helpContent 同期（課金・ペイウォール・復元の説明キー追加）。
