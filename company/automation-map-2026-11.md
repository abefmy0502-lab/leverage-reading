# 自動化の地図（2026-11-23）

> オーナー「可能な限り質を上げた状態で、自動化ができるところはしていきたい。何を自動化できるのかを徹底的に調べて仕組み化して」への答え。
> 中期計画の 16 の課（`scripts/plan/schedule.mjs` の ROLES）の仕事を 1 つずつ見て、**自動（Claude が回す）／半自動（Claude が下書き・オーナーが決める）／人（理由つき）**に分けた。
> 自動にする条件は 1 つ：**質の関所（テスト・点検・数字）を通らないものは外に出さない**。関所の無い自動化は作らない。

## 0. 結論

- **いま自動で動いているもの 6 つ＋今回足した 4 つ＝10 の仕組み**（§1）。オーナーの手が要るのは「決める・返信する・顔と声・お金と契約」だけに寄せた。
- 自動にしないと決めたもの（§3）：**SNS の返信**（会話が勝ち筋・規約）、**お金・契約・審査の提出**、**利用者のデータの削除**、**仕様の判断**。
- 質の関所：テスト 2,000 本超（CI）・投稿の機械の点検（`weekly-drafts.mjs --check`・場ごと）・画面の採点（ui-critic 16/20）・数字の見直し（毎週月曜）。

## 3. 自動にしないもの（理由）

| もの | 理由 |
|---|---|
| SNS の返信・ほかの人への返信 | 勝ち筋そのもの（X は返信・引用が重い・Threads は返信が主役）。X は言葉で探して自動で返信するのを禁止 |
| お金・契約・App Store の提出と公開・価格 | 取り消しにくい・責任が人（オーナーの OK が要る決まり） |
| 利用者のデータの削除・退会・SQL の破壊的な変更 | 取り消せない |
| 仕様の判断・計画の数字の変更 | 価値の判断はオーナー（自動は案まで） |
| 顔・声の要る 1 本 | 本人にしか作れない |

## 4. 質を落とさないための約束

1. **関所の無い自動化は作らない**（テスト・点検・数字のどれか 1 つ以上）。
2. **自動の仕事は報告を 1〜5 行で出す**（何もなければ 1 行）。通知はプッシュ。
3. **失敗は直そうとせず記録する**（自動のセッションは 2 回直して戻らなければ止める）。
4. **数字は実数だけ**。20 人未満の率は出さない。推測は推測と書く。
5. **止め方は 1 つ**：claude.ai/code の「スケジュールされたタスク」で止める（Claude に「〜を止めて」でもよい）。

## 5. 次に自動にできるもの（条件が整ったら）

| もの | 条件 |
|---|---|
| App Store の入手（`ct=`）の取り込み | App Store Connect の API の鍵（オーナーが発行）→ 月曜の見直しが入口別・機能別の入手を自動で読む |
| SNS の数字（届いた数・保存・送信）の取り込み | 各 SNS の API の鍵と権限（Instagram はビジネスのアカウント） |
| クラッシュの見張り | Sentry の DSN（いまは未設定） |
| TikTok の予約 | 予約の仕組みが TikTok に対応したら |
