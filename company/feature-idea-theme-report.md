## 1. 何をする機能か
ユーザーが貯めた **メモ（カード式/まとめ式）＋ 読書計画（セットアップシート：投資目的/課題/仮説/選書理由）＋ タグ** を、**カテゴリ/テーマ単位（例：営業）でAIが横断的に統合**し、**①レポート（文章）** または **②図解（マインドマップ/関係図）** として出力する。
- 例：「営業」を選ぶ → 営業に関する複数冊のメモ・計画を束ねて、**「営業の要点・共通パターン・矛盾点・あなたへの行動提案・引用元の本」**を1枚のレポートに。
- 一言：**「あなたの読書が、1枚のレポート（or 1枚の地図）になる。」**

## 2. なぜ強いか（CEO評価）
1. **思想に直結**：読みっぱなしをやめ、知識を"使える資産"に。Orimeの核そのもの。
2. **マイ読書脳の自然な拡張**：今は"問いに答える(入力)"。これは"テーマを統合して出力する"＝対の機能。基盤を再利用できる。
3. **プレミアムの理由になる**：競合（記録系）に無い。¥1,280〜の有料を正当化する"why pay"の主役になり得る。
4. **リテンション**：メモが増えるほどレポートが良くなる＝**貯める動機**になる（複利）。
5. **マーケ資産**：「読書が1枚のレポートに」は**超demoable**。X/Note/ASOスクショ/プレビュー動画の主役にできる。

## 3. 実現性（技術・このスタックで）
- **データ源は既に揃っている**：`book_memos`（card/summary/personal）・`tags`（personal学びは `@カテゴリ`）・setup fields（`current_challenge`/`hypothesis`/`book_reason`）。カテゴリ抽出はタグ/テーマで可能。
- **レポート＝実現性 高**：既存の AI 基盤（`api/claude.js` + `prompts.js` + ストリーミング）と Markdown レンダ（`MarkdownSections`）を**そのまま再利用**。新規プロンプト（例 `themeReport`）＋「カテゴリのメモを集めて渡す」処理だけ。**MVPは小さい**。
- **図解＝実現性 中**：Claude に **Mermaid 記法**（マインドマップ/関係図）を生成させ、`mermaid` ライブラリで描画。リッチな図が出せるが、**依存追加・CSP・bundle増**のコスト。→ V2で。
- **コスト**：大コーパス統合は入力トークンが膨らむ → **実装済みのAI利用量メータリング**＋1レポートの抽出上限/`max_tokens`で制御。

## 4. 機能の形（MVP → V2）
- **MVP（レポート）**：マイ読書脳 or 新サーフェスで「テーマ/カテゴリを選ぶ → 生成」。出力は構造化Markdown（概要／主要な学び／共通パターン／矛盾・対立／あなたへの行動提案／引用元の本）。保存・エクスポート可。
- **V2（図解）**：「図解」トグル → Mermaid のマインドマップ/関係図で同テーマを可視化。
- **思想ガード**：**1タップで"魔法"**。複雑なビルダーにしない（カテゴリ選ぶ→出てくる、だけ）。
